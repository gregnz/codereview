# Plan 07-01: Architectural Genesis & Code Emergence Story Engine

## Goal
Transform the workbench UI and analyzer into an intuitive **'I built this from scratch' Architectural Genesis Storyline**, where the developer travels through the progressive problem-solving steps that birthed the codebase, seeing the architecture graph emerge node-by-node with rich authorship rationale.

## The Genesis Chapters for FastMail (`~/projects/mail`)
1. **Chapter 1: The Problem & Local Storage Foundation**
   - *Problem*: Fast offline email reading without network lag.
   - *Architecture*: SQLite schema, `store.go`, `LocalStore` struct, FTS5 full-text indexing.
2. **Chapter 2: Authentication & Token Management**
   - *Problem*: Connecting to Gmail API securely.
   - *Architecture*: Google OAuth2 authorization code flow, token storage in `~/.fastmail`, `auth.go`, `AuthService`.
3. **Chapter 3: Background Synchronization & Concurrency**
   - *Problem*: Fetching 10k emails in background without freezing the UI.
   - *Architecture*: Background goroutines, `sync.go`, `SyncEngine`, `syncMu` mutex (preventing duplicate syncs), `mu` (account switching).
4. **Chapter 4: Ingestion Security & Tracker Protection**
   - *Problem*: Untrusted email bodies containing tracking pixels and scripts.
   - *Architecture*: `sanitizer.go`, `classifier.go`, stripping 1x1 image beacons, inbox categorizations (Main, Newsletters, Updates).
5. **Chapter 5: Desktop Orchestration & Wails IPC Bridge**
   - *Problem*: Connecting backend Go state to desktop window.
   - *Architecture*: `main.go`, `app.go`, `App` orchestrator, Wails method bindings, runtime event emission (`wailsRuntime.EventsEmit`).
6. **Chapter 6: Svelte Reactive Experience**
   - *Problem*: Instant, keyboard-driven desktop email reading.
   - *Architecture*: `frontend/src/App.svelte`, 3-pane layout, j/k navigation, reactive stores.
